## 4. ТРЕБОВАНИЯ К ПРОГРАММЕ

### 4.1. Требования к функциональным характеристикам

#### 4.1.1. Управление заметками

**4.1.1.1. Создание заметок**

Программа должна обеспечивать:
- Создание заметок двух типов:
  - Текстовые заметки (NoteType.TEXT)
  - Чеклисты (NoteType.CHECKLIST)
- Выбор типа заметки через диалоговое окно (Bottom Sheet)
- Автоматическое присвоение уникального идентификатора (ID)
- Сохранение временной метки создания (timestamp)

**4.1.1.2. Просмотр заметок**

Программа должна обеспечивать:
- Отображение списка всех заметок в главном окне
- Сортировку заметок по времени последнего изменения (новые сверху)
- Визуальное различие между типами заметок:
  - Цветовой индикатор типа заметки
  - Превью содержимого:
    - Для текстовых заметок: первые 80 символов текста
    - Для чеклистов: количество выполненных/всего задач
- Отображение заголовка заметки или "(Без названия)" при отсутствии заголовка
- Открытие заметки при клике для просмотра/редактирования

**4.1.1.3. Редактирование заметок**

Программа должна обеспечивать:
- Изменение заголовка заметки
- Редактирование содержимого текстовой заметки
- Добавление, изменение, удаление элементов чеклиста
- Отметку элементов чеклиста как выполненных/невыполненных
- Автоматическое обновление временной метки изменения
- Валидацию: запрет сохранения полностью пустых заметок

**4.1.1.4. Удаление заметок**

Программа должна обеспечивать:
- Удаление заметки по длинному нажатию (long click)
- Запрос подтверждения удаления
- Каскадное удаление связанных данных:
  - Файловых вложений из базы данных
  - Физических файлов из внутреннего хранилища

#### 4.1.2. Работа с чеклистами

**4.1.2.1. Функциональность чеклистов**

Программа должна обеспечивать:
- Создание списков задач с checkbox элементами
- Добавление новых элементов чеклиста
- Редактирование текста каждого элемента в реальном времени
- Переключение состояния checkbox (выполнено/не выполнено)
- Удаление отдельных элементов чеклиста
- Сохранение порядка элементов
- Отображение прогресса: N/M выполнено

**4.1.2.2. Структура данных чеклиста**

Каждый элемент чеклиста содержит:
- Уникальный идентификатор (UUID)
- Текст задачи
- Состояние выполнения (boolean)

Данные хранятся в формате JSON в поле checklistItems таблицы notes.

#### 4.1.3. Работа с файловыми вложениями

**4.1.3.1. Добавление файлов**

Программа должна обеспечивать:
- Прикрепление файлов любых типов к заметке
- Выбор файлов через системный файловый менеджер (ACTION_OPEN_DOCUMENT)
- Копирование файлов во внутреннее хранилище приложения (internal storage)
- Сохранение метаданных файла:
  - Оригинальное имя файла
  - MIME-тип
  - Размер файла в байтах
  - Путь к файлу
  - Временная метка добавления

**4.1.3.2. Просмотр вложений**

Программа должна обеспечивать:
- Горизонтальный список прикрепленных файлов (RecyclerView)
- Отображение для каждого файла:
  - Иконки типа файла или thumbnail для изображений
  - Имени файла
  - Размера файла в удобочитаемом формате (B, KB, MB, GB)
- Визуальное различие типов файлов:
  - IMAGE: thumbnail изображения
  - DOCUMENT: иконка документа
  - AUDIO: иконка аудио
  - VIDEO: иконка видео
  - OTHER: общая иконка файла

**4.1.3.3. Открытие файлов**

Программа должна обеспечивать:
- Открытие файлов в соответствующих приложениях при клике
- Использование FileProvider для безопасного предоставления URI
- Предоставление временных разрешений на чтение (FLAG_GRANT_READ_URI_PERMISSION)
- Обработку отсутствия подходящих приложений для открытия

**4.1.3.4. Удаление вложений**

Программа должна обеспечивать:
- Удаление отдельных файлов из заметки
- Удаление записи из БД
- Удаление физического файла из хранилища

#### 4.1.4. Хранение данных

**4.1.4.1. Архитектура базы данных**

Программа использует Room Database со следующей структурой:

**Таблица notes:**
| Поле | Тип | Описание |
|------|-----|----------|
| id | Long | Первичный ключ, автоинкремент |
| title | String | Заголовок заметки |
| content | String | Содержимое текстовой заметки |
| type | NoteType | Тип заметки (TEXT/CHECKLIST) |
| checklistItems | JSON String | Массив элементов чеклиста |
| updatedAt | Long | Временная метка последнего изменения |

**Таблица file_attachments:**
| Поле | Тип | Описание |
|------|-----|----------|
| id | Long | Первичный ключ, автоинкремент |
| noteId | Long | Внешний ключ на notes(id) |
| filePath | String | Относительный путь к файлу |
| fileName | String | Имя файла |
| mimeType | String | MIME-тип файла |
| fileSize | Long | Размер файла в байтах |
| timestamp | Long | Временная метка добавления |

**Связи:**
- file_attachments.noteId → notes.id (CASCADE DELETE)
- Индекс по noteId для оптимизации запросов

**4.1.4.2. Миграции БД**

- Migration 1→2: Добавление полей type и checklistItems
- Migration 2→3: Добавление поля attachedFiles
- Fallback к деструктивной миграции при ошибках

#### 4.1.5. Пользовательский интерфейс

**4.1.5.1. Главный экран (MainActivity)**

Должен содержать:
- App Bar с заголовком "Заметки" и подзаголовком
- RecyclerView со списком заметок в виде карточек
- FloatingActionButton для создания новой заметки
- Состояние "Пусто" при отсутствии заметок
- ProgressBar при загрузке данных
- Анимацию скрытия FAB при прокрутке

**4.1.5.2. Экран редактирования (EditNoteActivity)**

Должен содержать:
- Toolbar с кнопкой назад
- Поле ввода заголовка (TextInputEditText)
- Динамический контент в зависимости от типа:
  - Для TEXT: многострочное поле ввода текста
  - Для CHECKLIST: RecyclerView с элементами чеклиста и FAB для добавления
- RecyclerView с прикрепленными файлами (горизонтальная прокрутка)
- Кнопка "Прикрепить файл"
- Кнопка "Сохранить"

**4.1.5.3. Диалог выбора типа (NoteTypeSelectionDialog)**

Bottom Sheet диалог с карточками:
- Текстовая заметка (иконка 📝)
- Чеклист (иконка ☑️)

Каждая карточка содержит:
- Иконку в цветном круге
- Название типа
- Краткое описание
- Стрелку навигации

#### 4.1.6. Архитектура приложения

**4.1.6.1. Паттерн MVVM**

Программа реализована по паттерну Model-View-ViewModel:

- **Model:**
  - Note (data class)
  - FileAttachment (data class)
  - ChecklistItem (data class)
  - Enum классы: NoteType, FileType

- **View:**
  - Activities: MainActivity, EditNoteActivity
  - Dialogs: NoteTypeSelectionDialog
  - Adapters: NoteAdapter, ChecklistAdapter, FileAttachmentAdapter

- **ViewModel:**
  - NoteViewModel (список заметок)
  - EditNoteViewModel (редактирование)
  - NoteDetailViewModel (детали и вложения)

**4.1.6.2. Repository паттерн**

- NoteRepository: работа с заметками
- FileAttachmentRepository: работа с вложениями

**4.1.6.3. DAO (Data Access Objects)**

- NoteDao: CRUD операции с заметками
- FileAttachmentDao: CRUD операции с вложениями

**4.1.6.4. Utilities**

- FileManager: управление файлами в internal storage
- Result: sealed class для обработки результатов операций
- Converters: JSON сериализация/десериализация

### 4.2. Требования к надежности

#### 4.2.1. Обеспечение надежного функционирования

Программа должна обеспечивать:
- Отсутствие потери данных при аварийном завершении
- Корректную обработку исключений (try-catch блоки)
- Graceful degradation при ошибках
- Автоматическое восстановление после сбоев

#### 4.2.2. Контроль входных данных

Программа должна обеспечивать:
- Валидацию пользовательского ввода
- Проверку существования файлов перед операциями
- Обработку некорректных данных из БД
- Защиту от SQL инъекций (параметризованные запросы через Room)

#### 4.2.3. Требования к обработке ошибок

Программа должна:
- Отображать понятные сообщения об ошибках пользователю
- Логировать критические ошибки
- Не допускать crash приложения при ошибках ввода-вывода
- Предоставлять возможность повторить неудавшуюся операцию

#### 4.2.4. Требования к резервному копированию

Программа должна:
- Хранить данные в стандартной БД SQLite
- Поддерживать Android Auto Backup (если включено в ОС)
- Предоставлять путь к БД для ручного резервного копирования

#### 9.4.2. Паттерны проектирования

- **Type Converters** - конвертация сложных типов для Room
